# Central tool catalog: truth and limitations

`src/rei_rea/data/tools.json` is generated by `scripts/generate_catalog.py`, and read by CLI, MCP, planner and dashboard.

## Registry semantics

| Field | Meaning |
| --- | --- |
| `id` | Stable tool identifier for lookup |
| `category`, `tags` | Route to a relevant artifact and skill |
| `executables` | Candidate local executable names, not versions |
| `homepage` | Upstream reference (verify terms and actual releases before installation) |
| `integration` | `static-adapter` for one of 9 fixed commands, otherwise `discovery-only` |
| `bundled: false` | No third-party binary or license included |
| `installed` | Computed at runtime from PATH; **does not prove functionality** |

## Highlights

- Native: Ghidra, IDA/Hex-Rays, Hopper, Binary Ninja, Cutter, radare2/Rizin, GDB, LLDB, x64dbg, WinDbg, rr.
- Symbolic/emulation: angr, Qiling, Unicorn, Triton, Miasm, Manticore, QEMU.
- Windows/.NET: ILSpy, dnSpyEx, ildasm, monodis, PE-bear, DIE, capa, FLOSS.
- Android/mobile: JADX, Apktool, AAPT2, ADB, dex2jar, baksmali, Androguard, MobSF, Frida, Objection, JEB.
- Firmware/IoT: Binwalk, ubi_reader, Jefferson, UEFITool, CHIPSEC, flashrom, dtc, SquashFS tools.
- Browser/network: Chrome, Playwright, Semgrep, asar, mitmproxy, Wireshark, tshark, tcpdump, Scapy, protobuf, grpcurl, ZAP.
- WASM/managed: WABT, Wasm-tools, Binaryen, Java javap/CFR, .NET IL tools.
- Format/evidence: Kaitai Struct, ImHex, 010 Editor, LIEF, ExifTool, hashdeep, YARA-X, Volatility3, jq, SQLite.

Do not automate software installation, license acquisition or setup through the hub without a separate explicit proposal and review. Commercial apps remain subject to their vendors' licenses.

## Adding an adapter

1. Add a truthful tool entry to `scripts/generate_catalog.py` and regenerate `tools.json`.
2. For a static executable adapter, register a **fixed** argument tuple in `registry.STATIC_ADAPTERS`, add the ID to `ADAPTERS` in catalog generation and review executable substitution.
3. Write unit/integration tests (including malformed inputs, timeouts and untrusted filenames).
4. Update docs and MCP contracts only if the tool produces new verified capabilities; do not silently broaden permissions.
5. Run the full test suite, document rollback and the exact provider version validated.
